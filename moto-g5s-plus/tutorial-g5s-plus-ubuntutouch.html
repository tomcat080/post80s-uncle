二、来路：从出厂到 Ubuntu Touch

🙏 原始出处（第三方移植，非官方）
原始仓库：EEMuk/ubuntu-touch-motorola-sanders（作者 EEMuk，2026-10-23 创建）
配套内核：EEMuk/android_kernel_motorola_sanders（分支 halium-11，基于 PixelExperience 11 的 3.18 内核 + Halium + AppArmor + 驱动修复）
唯一 release：24.04-20261023（2026-10-23 发布）。本机 apt 源 deb http://repo.ubports.com/ 24.04-1.x main 与该移植通道一致。

安装步骤（整理自 EEMuk 仓库 README，非本文原创）

前置：① 解锁 Bootloader，电脑装 fastboot；② 备份 persist / modemst1 / modemst2 / fsg（存 IMEI 与校准数据，丢了找不回）。

从 latest release 下载 boot.img、vendor-pe11-sanders.zip、ubuntu.zip，解压后进 bootloader：

fastboot flash oem vendor-pe11-sanders.img
fastboot flash boot boot.img
fastboot flash system ubuntu.img
fastboot erase userdata        # 会清空手机全部数据
fastboot reboot                # 首次启动格式化 userdata，需几分钟

要点：vendor-pe11-sanders.img 是原版 PixelExperience 11 vendor，无需先刷 PE11；此机 vendor 分区在 oem，故替换原厂 oem。fastboot -w 在此 bootloader 上无效（报不出分区大小）。

功能状态（原仓库实测）：显示/触控/GPU/视频、WiFi/热点/蓝牙、通话(VoLTE/2G)/短信/移动数据、前后摄与录像、GPS、指纹与传感器、USB MTP/网络共享、Waydroid 均可用；NFC/FM 收音机、ViLTE 视频通话不支持；双卡/MMS、有线耳机未测。
已知问题：24.04-20261023 首装后时钟可能错约 30 分钟（网站报证书错误），开关一次 WiFi 即同步；待机耗电约 2–3%/小时（原仓库称下一版修复，但未发布）。
回退安卓：按常规刷回 ROM 或备份即可。

本机脉络

  1. 出厂 Android 8.1（first_api_level=27 证实），一路 OTA 被抬到 Android 11。
  2. 解锁 Bootloader → 刷入上述 EEMuk 移植的 Ubuntu Touch 24.04.5 LTS（noble / Halium 11 底座）。
  3. 系统落定后网络与 SSH 默认都关闭 —— 后续折腾全部围绕「把它变成可远程操作的 Linux 小主机」展开。

UBports 官方设备页 devices.ubports.com/#/sanders 仅作机型参考，该机不在官方 OTA 支持列表。

SSH 打通（2026-11-04）

默认连不上是因为：ssh.socket/ssh.service 都 disabled，且 50-lxc-android-config.conf 写死 PasswordAuthentication=no。三步落地，全部持久：

# 1) 00- 排在 50- 之前，sshd 采用 first-value-wins
sudo tee /etc/ssh/sshd_config.d/00-tom-local.conf <<'EOF'
PasswordAuthentication yes
KbdInteractiveAuthentication no
PermitRootLogin no
PubkeyAuthentication yes
EOF

# 2) Mac 公钥写入 authorized_keys
cat ~/.ssh/id_ed25519.pub | ssh phablet@<手机IP> 'mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys'

# 3) 启用 ssh.socket（开机自启）
sudo systemctl enable --now ssh.socket

三条通道实测全通：WiFi 公钥免密、WiFi 密码、adb forward tcp:2222 tcp:22 的 USB 转发。会话内 sudo 提权 root 成功，开机自启在重启后复测通过。

回滚：sudo rm /etc/ssh/sshd_config.d/00-tom-local.conf + sudo systemctl disable --now ssh.socket + 删掉对应公钥。

三、Waydroid：在 Ubuntu Touch 里跑 Android 13

地基全现成：waydroid 1.5.1 系统自带，内核 3.18.140-halium 已带全套 binder 节点与 ASHMEM / USER_NS / CGROUPS 等必需选项。没有 /dev/kvm → 全虚拟化不可行；无 binderfs → Docker/redroid 不可行。

镜像托管在 SourceForge，直连仅 ~84KB/s（870MB 要 3 小时）。按实测配方走 16 线代理并发，121 秒下完：

# 关键坑：先 HEAD 解析带签名的最终地址，不能直接给 aria2 一个 /download 页面
URL=$(curl -sS -I -L -o /dev/null -w '%{url_effective}' "<sourceforge 页面>")
aria2c "$URL" --all-proxy=http://127.0.0.1:12334 -x16 -s16 -k1M --user-agent=Mozilla/5.0
  • system：lineage-20.0-20260927-VANILLA-waydroid_arm64-system.zip（870MB / 121 秒）
  • vendor：lineage-18.1-20260402-HALIUM_11-waydroid_arm64-vendor.zip（41MB / 17 秒）
  • 两个 zip 的 SHA256 与 OTA 清单完全一致，确认官方原包。
# 镜像放 /home（根分区只剩 686M，system.img 有 1.86GiB）
mkdir -p /home/phablet/waydroid-images/images
sudo mount -o remount,rw /
sudo ln -s /home/phablet/waydroid-images/images /etc/waydroid-extra/images
waydroid init   # 命中预置镜像、跳过 OTA

实测：Session / Container 均 RUNNING，Android 13（LineageOS 20），152 个包，launcher3 / system_server / surfaceflinger 全在跑。代价是常驻约 484MB 内存。

四、WiFi 假断线根治 + 静态 IP（2026-11-26）

症状：熄屏一段时间后，WiFi 图标仍显示已连接，实际数据流已断。断久了 DHCP 租约失效 → 重连换 IP（本机从 172.16.9.29 漂到 172.16.12.36）→ 按旧 IP SSH 全部超时。

根因：NetworkManager 全局省电 /etc/NetworkManager/conf.d/default-wifi-powersave-on.conf 写死 wifi.powersave = 3。该文件在只读根分区，改不了 —— 但可以在连接级覆盖。

sudo nmcli connection modify "K2P" \
  ipv4.method manual \
  ipv4.addresses 172.16.12.36/21 \
  ipv4.gateway 172.16.10.1 \
  ipv4.dns "114.114.114.114" \
  wifi.powersave 2          # 2 = disable，覆盖全局的 3
sudo nmcli connection up "K2P"

验证：路由从 proto dhcp 变 proto static，powersave=disable，ping 0 丢包，SSH 重连成功。回滚：sudo nmcli connection modify "K2P" ipv4.method auto wifi.powersave 0 再 up。

静态 IP 钉在设备上，若路由器 DHCP 日后把 172.16.12.36 分给别人会冲突（当前是它在用，风险低）。彻底稳妥需在路由器做 DHCP 保留，本次按需求未动路由器。
