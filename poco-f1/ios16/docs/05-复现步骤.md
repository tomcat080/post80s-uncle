# 05 · 复现步骤：POCO F1 从 Android 到 iOS 16 桌面

> 适用：POCO F1（beryllium / SDM845）。全程需要解锁 BL。**每一步都可能把设备刷坏，先做备份。**
> 本流程已在真机上跑通到"进桌面 + SSH 可操作"，蓝牙用户态仍在推进中。

## 0. 前置

| 需要 | 说明 |
|---|---|
| `fastboot` / `adb` | `~/android-sdk/platform-tools/` |
| 串口式内核日志接收 | 内核把 console 以 UDP 发到 `192.168.7.1:5140`，Mac 侧 `en13` 配 `192.168.7.1/24` |
| 文件 | iOS16 root sparse 镜像（12.1 GB）、shim boot.img、TWRP |
| 外置盘 | 根镜像动辄 12–21 GB，别放系统盘 |

设备标识用 `-s` 锁死，避免刷到别的机器：

```bash
FB=~/android-sdk/platform-tools/fastboot
$FB devices                     # 认准 serial，例如 2b8c9438
```

## 1. 解锁 BL + 刷 TWRP

```bash
$FB -s 2b8c9438 flashing unlock
$FB -s 2b8c9438 boot twrp-3.7.0_9-0-beryllium.img
```

TWRP 里 `adb devices` 应出现 `recovery`。**iOS 镜像一旦跑起来，USB 描述符就不是 fastboot/adb 了，必须冷启动或重新 `fastboot boot`。**

## 2. 先做全量备份（不可跳过）

TWRP 下导出所有分区 + GPT，冷备到服务器并逐件 `sha256sum -c` 核对。至少覆盖：

```
modem / modemst1 / modemst2 / persist / persistbak / fsg / fsc / bluetooth / dsp
misc / frp / limits + 双 GPT（head/tail）
```

`persist` 和 `modemst*` 丢了就再也回不到能打电话的 Android。

## 3. 写入 iOS 根文件系统

```bash
$FB -s 2b8c9438 flash userdata ios16-root.simg
```

根镜像是 sparse HFS+，直接刷 `userdata`（约 237M 扇区）。刷完**不要**再格式化 userdata。

## 4. 启动镜像：用 shim，不要用原生 boot

POCO F1 的 ABL 只会跳进 Android 内核格式，所以要用 `shim`：它先做 SoC 上电（USB3 prim GDSC + 时钟主控），再按 `SWEETXNU` payload 平铺 xnu 的段，最后跳 `entry_va`。

```bash
$FB -s 2b8c9438 boot shim-boot-aks2.img
```

`fastboot boot` 完成约 0.5 秒，内核真正跑起来到 USB 网卡出现约 15 秒，SSH 端口约 70–90 秒可用。

## 5. Mac 侧网络

```bash
# en13 每次重启都会丢 IP
osascript -e 'do shell script "ifconfig en13 inet 192.168.7.1 netmask 255.255.255.0 up" with administrator privileges'
ping -c1 192.168.7.2
nc -z 192.168.7.2 22
```

## 6. SSH 与文件传输

```bash
SSHOPTS="-o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null \
  -o ConnectTimeout=10 -i $HOME/.ssh/id_ed25519 -o IdentitiesOnly=yes"
ssh $SSHOPTS root@192.168.7.2 'uname -a'
```

设备上**没有 scp 子系统**，传文件只能：

```bash
ssh $SSHOPTS root@192.168.7.2 'toybox cat > /usr/local/bin/foo' < ./foo
ssh $SSHOPTS root@192.168.7.2 'toybox chmod 755 /usr/local/bin/foo'
```

注意：设备 `toybox` 没有 `sh` applet，`/bin/sh` 需要指向自编 `minish`（或 V3 覆盖版），否则很多 `popen`/脚本会失败。

## 7. 抓内核日志

```bash
python3 - <<'EOF'
import socket
s=socket.socket(socket.AF_INET,socket.SOCK_DGRAM)
s.setsockopt(socket.SOL_SOCKET,socket.SO_REUSEADDR,1)
s.bind(('0.0.0.0',5140))
with open('/tmp/console.log','ab',buffering=0) as f:
    while True:
        d,_=s.recvfrom(65535); f.write(d)
EOF
```

一个端口只能一个进程占用，旧的抓包进程要先杀掉，否则新进程报 `Address already in use`。
没有 live 抓包时的替代：userdata 末尾 4 MiB 持久日志区，`dd bs=4096 skip=29643770 count=1025`（按当前分区大小算），再 `tools/sweet-log.py` 解码。

## 8. 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| `fastboot reboot normal` 报 unknown | ABL 不支持 | 用 `fastboot boot` 或手动按键 |
| USB PID 变 `0xd00d` | `fastboot reboot` 回落到 fastboot | 冷启动 |
| 进系统但网络不通、SSH 拒连 | USB3 prim GDSC / 时钟主控未上电 | 必须用带 shim 上电修复的镜像 |
| 黑屏、每帧 `kIOReturnBadArgument` | IOMFB 结构错配（`0x514` vs iOS16 `0x46c`） | 换正确谱系的内核，别硬修 |
| `No bluetooth on this device` | 设了 `BT_DEVICE_ADDRESS` | **删掉该环境变量**，用 `BT_HCI_TRANSPORT` |
| 内核"编译成功"但 BT/显示全无 | 补丁集不是 beryllium 谱系 | 比对 `sweetbt`/`sweetwlan` 字符串条数 |
| `scp` 报 subsystem 失败 | 设备无 scp 子系统 | 用 `ssh 'toybox cat > …'` |

## 9. 回滚

```bash
# 回到 Android（先解 BL 状态下的原厂 boot）
$FB -s 2b8c9438 flash boot boot-stock-V12.0.3.0.QEJMXIM.img
$FB -s 2b8c9438 flash userdata <之前 dump 的 userdata 或直接 wipe>
```

日常调试用 `fastboot boot`（不改分区）；确认稳定后再固化：`$FB -s 2b8c9438 flash boot shim-boot-aks2.img`（2026-11-22 已对 `2b8c9438` 执行过一次，冷启动验证通过）。
