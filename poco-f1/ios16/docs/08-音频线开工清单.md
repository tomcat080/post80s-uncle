# 08 - 音频线开工清单（P0 盘点）

状态：只读盘点完成，未改内核、未刷机。以下每条都在真机/本机构建产物上核过。

## 1. 系统侧现状（iOS 16.7.16 image）

| 事实 | 证据 | 含义 |
|---|---|---|
| 音频 HAL 插件被禁用 | `/Library/Audio/Plug-Ins/HAL/` 为空；`VirtualAudio.plugin` 在 `HAL.disabled/` | v12 起为了不让 `mediaserverd` 反复 SIGSEGV 手动挪走的 |
| 没有虚拟音频设备 | `sweetps` 里没有 media/audio 常驻；`/dev` 无 audio/pcm 节点 | 插件找不到可用的 VAD，`vdef` 不存在 → HAL 里拿不到默认设备 |
| 没有 `/product/audio` 设备树节点 | `beryllium-16.adt` 里 `\0audio\0` 计数为 0；插件里写死 `IODeviceTree:/product/audio` | 插件启动时连"有哪些端口"都读不到 |
| 内核里没有音频类 | `kernel.development.sweet` 里 `IOAudio*` 命中 0，只有 `COREAUDIO` 字样 | 既没有 `IOAudioFamily`，也没有 `AppleEmbeddedAudio` 这类内置驱动 |
| 内核有 DriverKit 基础设施 | kernel 里有 `dext` 启动/rematch/UniqueID 整套字符串，`IOUserServer` 相关 29 处 | dext 机制在，缺的是音频 dext 本身 |
| 设备上没有音频 dext | `/System/Library/DriverExtensions` 只有 HID×2、BCMWLAN、E1000/IXGBE/IXL、ECM | 没法"直接加载 Apple 的音频驱动" |

`VirtualAudio.plugin`（6,657,136 B，已取回本机 `/tmp/VirtualAudio.bin`）的关键 strings：

```
IODeviceTree:/product/audio
VirtualAudioDevice_Default / _Music / _LowLatency / _CallContinuity / _SiriOutput ...
Created DriverKit device
kAppleEmbeddedAudio_DevicePropertyInputEnableDevice
com.apple.audio.virtualaudio
```

结论：iOS 16 的音频是 **HAL 插件（用户态）+ 内核/dext 驱动**两层。插件负责路由与端口策略，
真正的流由驱动侧（DriverKit AudioDriverKit，或内置 `AppleEmbeddedAudio`）提供。
两者在这台机器上都缺。

## 2. 硬件侧事实（beryllium / SDM845）

Linux 主线 DTS（`sdm845-xiaomi-beryllium-common.dtsi` + `sdm845-wcd9340.dtsi`）给出的链路：

```
Q6ADSP 固件（q6afe / q6asm） --> SLIMBUS_0_RX --> WCD9340 codec
                                                   ├─ codec@1,0 (slim217,250), ifd@0,0 同总线
                                                   ├─ SoundWire master swm@c85 (v1.3.0, 6 dout / 2 din)
                                                   ├─ MCLK = RPMH_LN_BB_CLK2, 9.6 MHz
                                                   └─ IRQ = TLMM gpio 54
```

要点：
- **codec 只在 SLIMbus 上**，SLIMbus 主控在 SDM845 上是 LPASS 里的 NGD，**由 ADSP 固件驱动**
  （Linux 侧是 `qcom,slim-ngd`，走 GLINK/QMI 到 ADSP，不是 HLOS 直接寄存器操作）。
- 扬声器功放挂在 codec 内部的 SoundWire（`swm`），同样要 codec 先活。
- 因此"真出声"的必要条件 = **ADSP 起来**（PIL 加载 `adsp` 分区固件）+ Q6AFE 路由 + codec 初始化。
  这比 MSS/MBA 那套只多不少：ADSP 是完整 DSP 固件（几十 MB 级），还带 GLINK/QRTR/QMI 三件套。

## 3. 两条可选路线（成本差一个数量级）

### 路线 A：先让音频栈"活着"（不发声，纯软件）
- 目标：CoreAudio/HAL 里出现一个可用设备，`mediaserverd` 不再崩，音量键/系统提示音的
  路由逻辑能跑；后续换真驱动时上层不用重做。
- 做法：内核侧提供最小播放设备（`IOAudioFamily` 已在 Apple 开源仓库
  `apple-oss-distributions/IOAudioFamily`，可作为源码引入），ADT 里补 `/product/audio` 节点，
  再把 `VirtualAudio.plugin` 从 `HAL.disabled` 放回。
- 风险：低。不碰 EL3、不碰 ADSP；最差情况是设备起不来音频设备，系统照常。
- 代价：要给内核构建引入一个 kext 工程（`IOAudioFamily` 不是 xnu 自带）。

### 路线 B：真出声（ADSP + codec）
- 前置：ADSP PIL（`adsp` 分区固件加载/校验/启动）→ GLINK/QRTR → Q6AFE 配置 SLIMbus →
  WCD9340 上电/时钟/MCLK → SoundWire 枚举功放 → 才算"有声音"。
- 风险：高。和 MSS 那次同级别甚至更高（DSP 固件 + 多套 IPC），一旦 EL3/DSP 侧卡住，
  现场只能物理断电。
- 代价：至少 5-8 个真机闸门，且每个闸门都要断电重启。

## 4. 建议的第一闸门（A0.5，仍然只读）

1. 读 `adsp` 分区是否存在、`image/adsp.mbn`（或 `adsp.mdt` + 分段）大小；
2. 读 ADSP 相关时钟/复位状态（gcc adsp CBCR、QDSP6 ADSP halt 寄存器）；
3. 确认 ADSP 是否已被 ABL 拉起（若是，路线 B 少一大截；若在复位，就得先做 PIL）。

这三项都是只读 MMIO/分区读，可以并到一次 `sweetaudio=1` 的预检里，不改任何状态。

## 5. 结论

- 现在没有任何"半成品"可以复用：既没有音频 kext/dext，也没有 `/product/audio`。
- 路线 A 能在低风险下把 iOS 音频栈恢复到"有设备、不崩"，但不会有声音；
  路线 B 才能出声，代价等同再做一个 P3。
