# 04 · 内核重建通道（GitHub Actions 编 xnu）

Wi-Fi P3、音频、AKS 后续修复，全都要改内核。而本机没有 Xcode，`iphoneos` SDK 不存在，本地编不了 xnu。这条通道是本轮最重要的基础设施。

## 一、为什么必须走 CI

- 本机只有 CommandLineTools，缺 `iig`（Xcode 才带），xnu 的 IOKit 交互层生成不了；
- `brew install aarch64-elf-gcc` 在本机卡死，`shim/build.sh` 的本地交叉编译链不成立；
- 本机 `mkbootimg` 两份都不可用（一份是 32-bit Linux ELF），重打包要在 `tom-pan@192.168.200.209` 上做。

## 二、踩到的两个坑

### 坑 1：`macos-14` 已被 GitHub 下线（2026-11）

首次触发直接 5 秒失败：

```
The configuration 'macos-14-arm64-us-default' is not supported
```

GitHub 在 2026-11 撤掉了 `macos-14` 镜像，`runs-on: macos-14` 一律被取消。改成 `macos-15`（同样是 arm64）即可。

代价：`macos-15` 上最低只有 Xcode 16.x，没有原工作流想要的 Xcode 15.x。原注释说 Xcode 16 的 `iig` 会生成 `IORPC.kernelContent`、与 xnu-8796 不匹配——**实测没炸**：内核编译与运行都正常，说明这代 xnu 的 IORPC 结构能吃下 Xcode 16 的输出。

### 坑 2：fork 错了仓库，得到"编译成功但不能用"的假内核

第一版在 `dipa-studio/ios-sweet` 的 fork 上构建成功（8 分 48 秒），但产物一比对就露馅：

| 字符串 | 在用的可用内核 | 假内核 |
|---|---|---|
| `sweetbt` | 21 | **0** |
| `sweetwlan` | 6 | **0** |
| `sweetfb` | 24 | 3 |

原因：`dipa-studio/ios-sweet` 是 **sweet（Redmi Note 10 Pro）线**，补丁止于 `0081`；我们在用的谱系（`ry-diffusion/Bergamota`）有 **135 个补丁**，多出来的 `0104`–`0141` 才是 beryllium 专属（`0136-beryllium-bt-hci-kctl` 就在里面）。拿 sweet 线的内核刷 beryllium，等于蓝牙 kctl、fb 缩放、wlan 探针全没了。

> 教训：构建完先 `strings | grep -c`，条数与在跑内核一致再打包。

## 三、可用的通道：自建最小构建仓

`tomcat080/ios-xnu`（专用构建仓，不放别的）：

```
.github/workflows/xnu.yml     ← runs-on: macos-15
xnu/patches/*.patch           ← 本地 135 个补丁
xnu/patches/0142-sweet-aks-wrapkey.patch  ← 本轮新增（AKS WrapKey）
xnu/patches/*.sh              ← 3 个 stage 脚本
```

构建脚本本身（`blacktop/darwin-xnu-build`，`DXB_SHA 663906528d1cd5ea8fde7de6f16de73db9511549`）由工作流现拉，仓库里不需要放 xnu 源码。

关键工作流设置：

| 项 | 值 |
|---|---|
| `runs-on` | `macos-15` |
| `MACOS_VERSION` | `13.5`（xnu-8796） |
| `KERNEL_CONFIG` | `DEVELOPMENT` |
| `MACHINE_CONFIG` | `SWEET` |
| 超时 | 120 分钟 |
| 产物 | `xnu-kernel`（`kernel.development.sweet`，约 61 MB zip） |
| 实际耗时 | **约 10 分钟**（未命中 ccache 也这么快） |

工作流里唯一需要的改动是把 `ARCHS="x86_64 arm64e"` 补成含 `arm64`（`libfirehose_kernel` 只编 arm64e，而 SWEET 内核是纯 arm64）。

## 四、从产物到能刷的 boot.img

```bash
# 1. 下载（GitHub 单线程只有 38 KB/s，必须上 aria2）
curl -sI -H "Authorization: token $PW" "$ARTIFACT_URL" | grep -i location   # 拿签名直链
aria2c -x8 -s8 -k1M --all-proxy=http://127.0.0.1:12334 -o xnu-kernel.zip "$SIGNED_URL"
# 实测 3.6 MiB/s，61 MB 十几秒

# 2. 校验
unzip -q xnu-kernel.zip -d out && cd out && shasum -a 256 -c SHA256SUMS
strings -a kernel.development.sweet | grep -c sweetbt     # 应为 21

# 3. 打包 payload（ADT 与 cmdline 沿用现役镜像的，别改）
python3 tools/mkpayload.py kernel.development.sweet \
  shim/out/beryllium-16.adt payload.bin --cmdline "<现役 cmdline>"

# 4. 在服务器重打 boot.img（kernel 用现役镜像里解出来的 shim Image.gz-dtb）
scp payload.bin tom-pan@192.168.200.209:~/btaks/
ssh tom-pan@192.168.200.209 'cd ~/btaks && mkbootimg --header_version 1 \
  --kernel kernel --ramdisk payload.bin --base 0 --kernel_offset 0x8000 \
  --ramdisk_offset 0x1000000 --tags_offset 0x100 --pagesize 4096 \
  --os_version 16.0.0 --os_patch_level 2025-06 --cmdline "console=null" -o out.img'

# 5. 回来必须验两件事
python3 tools/unpack_bootv2.py out.img check/ && cmp check/ramdisk payload.bin && cmp check/kernel kernel
```
