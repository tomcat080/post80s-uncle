POCO F1 · beryllium · SDM845

把 iOS 16.7.16 跑到小米 POCO F1 上

xnu-8796 开发内核 + iOS 16.7.16 用户空间（iPhone X d22ap，未改动），纯 CPU 渲染，无 GPU 驱动。真机已进过锁屏与桌面，USB 网络与 SSH 可完全操作。

SDM845xnu-8796shim bootUDP console纯 CPU
先读这句：这是我在自己机器上的第一手记录，不是通用教程。刷机有风险，变砖自负；每一步都请先做备份。

一、准备

需要说明
fastboot / adb能用 -s <serial> 锁定目标机，避免刷错设备
iOS16 根文件系统sparse HFS+，约 12.1 GB，刷进 userdata
shim 启动镜像本页下方有下载；它不是原生 Android 内核，而是能把 xnu 拉起来的 loader
Mac 侧网络方案设备起来后会做 USB ECM 网卡，Mac 端配 192.168.7.1/24，设备是 192.168.7.2
外置硬盘根镜像 12–21 GB，别塞系统盘（我的 Mac 只剩 10 GB 可用）
三个必须记住的点：
  • UI 只认真机屏幕。QEMU、截图、别人的机器表现如何都不作数。
  • 不要设 BT_DEVICE_ADDRESS。iOS 16.7 的 bluetoothd 会把它 sscanf 后清零，直接判定“本机没有蓝牙”。
  • 刷机前先 dump 分区。persist、modemst1/2、双 GPT 丢了，就再也回不到能打电话的 Android。

二、步骤

1解锁 BL、进 TWRP

fastboot -s 2b8c9438 flashing unlock
fastboot -s 2b8c9438 boot twrp-3.7.0_9-0-beryllium.img
# TWRP 里 adb devices 应出现 recovery

注意：iOS 镜像一旦跑起来，USB 描述符就不是 fastboot/adb 了，必须冷启动或重新 fastboot boot。

2全量备份（不可跳过）

TWRP 下导出所有分区与 GPT，冷备到服务器，并逐件 sha256sum -c 核对。至少覆盖 modem / modemst1 / modemst2 / persist / persistbak / fsg / fsc / bluetooth / dsp / misc / frp / limits 与两套 GPT。

3写入 iOS 根文件系统

fastboot -s 2b8c9438 flash userdata ios16-root.simg

刷完不要再格式化 userdata。

4用 shim 启动，而不是原生 boot

POCO F1 的 ABL 只认 Android 内核格式，所以要先让 shim 上电（USB3 prim GDSC + 时钟主控）、按 SWEETXNU payload 平铺 xnu 段，再跳 entry_va。

fastboot -s 2b8c9438 boot shim-boot-aks2.img
# 0.5 秒回 OKAY；约 15 秒出 USB 网卡；70–90 秒 SSH 可用
↓ 当前验证版（含 AKS 修复） ↓ 回滚首选 全部资产 / 校验和 ↗

5Mac 侧配网

# en13 每次重启都会丢 IP
osascript -e 'do shell script "ifconfig en13 inet 192.168.7.1 netmask 255.255.255.0 up" with administrator privileges'
ping -c1 192.168.7.2
nc -z 192.168.7.2 22

6SSH 与传文件

SSHOPTS="-o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null \
  -o ConnectTimeout=10 -i $HOME/.ssh/id_ed25519 -o IdentitiesOnly=yes"
ssh $SSHOPTS root@192.168.7.2 'uname -a'

# 设备没有 scp 子系统，只能这样传
ssh $SSHOPTS root@192.168.7.2 'toybox cat > /usr/local/bin/foo' < ./foo
ssh $SSHOPTS root@192.168.7.2 'toybox chmod 755 /usr/local/bin/foo'

设备 toybox 没有 sh applet，/bin/sh 需要换成自编的 minish，否则大量脚本与 popen 会失败。

7抓内核日志（UDP console）

python3 - <<'EOF'
import socket
s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
s.bind(('0.0.0.0', 5140))
with open('/tmp/console.log', 'ab', buffering=0) as f:
    while True:
        d, _ = s.recvfrom(65535)
        f.write(d)
EOF

一个端口只能一个进程占用，旧抓包进程没杀会报 Address already in use。没有 live 抓包时，可读 userdata 末尾 4 MiB 持久日志区，再用 tools/sweet-log.py 解码。

三、排障

现象原因处理
fastboot reboot normal 报 unknownABL 不支持用 fastboot boot 或手动按键
USB PID 变 0xd00dfastboot reboot 回落 fastboot冷启动
进系统但没网、SSH 拒连USB3 prim GDSC / 时钟主控未上电必须用带 shim 上电修复的镜像
黑屏，每帧 kIOReturnBadArgumentIOMFB 结构错配（0x514 vs 0x46c）换正确谱系内核，别硬修补丁
No bluetooth on this device设了 BT_DEVICE_ADDRESS删掉该变量，改用 BT_HCI_TRANSPORT
内核“编译成功”但 BT/显示全无补丁集不是 beryllium 谱系比对 sweetbt/sweetwlan 字符串条数（应为 21 / 6）
scp 报 subsystem 失败设备无 scp 子系统用 ssh 'toybox cat > …'

四、回滚

# 回到 Android
fastboot -s 2b8c9438 flash boot boot-stock-V12.0.3.0.QEJMXIM.img
fastboot -s 2b8c9438 flash userdata <之前 dump 的 userdata>

日常调试建议只 fastboot boot，不改分区；确认稳定再考虑 flash boot 固化。
